# 观点台账

台账是**长期记忆，不是归档仓库**。写进去的东西将来要被翻出来对照，所以宁少勿滥。

## 二、什么够格

**入：** 能被数据验证的判断

| 类型 | 例子 |
|---|---|
| 事实 | 「Q3 外贸油轮主营 78 亿，上半年季均 53 亿」 |
| 因果链 | 「期租租金一次性做进 Q3，所以归母只增 20%」 |
| 预测 | 「Q4 主营 = 74×3×1.15 = 255 亿」 |
| 操作 | 「海油减到 20% 以下」「780 第一防线」 |
| 方法论 | 「类债券看股息率−国债，周期看 PB，成长看 PE」 |

**不入：**

- 情绪（「越想越气」「恐抛售过度」本身）
- 闲聊、生活、转发、吵架
- 纯复述新闻
- 没有时间窗和可检验条件的空话（「长期看好」）

**尺子：** 这条能不能影响持仓动作？能不能证伪某个假设？有没有给出新的可验证数据？
三条都不占，就不写。

### 入库前先自问：这条我要不要收尾？（2026-11-05 加）

过去 70 条里 65 条躺在「待验证」，0 条证伪——因为入库零成本、收尾高成本。所以加一条门槛：

- **能当场核的事实，先核再写。** 有公开接口的（季报、行情、海关、指数）当场查，查到就直接写「兑现 / 证伪」进库，不要先挂「待验证」。**不核就不写。**
- **预测必须带确切验证期限。** 写「2026Q4」不算，要写 `YYYY-MM-DD`（例如「2026-11-06 收盘」「2027-04-30 前」）。没验证期限的不许入库。
- **新增量砍半。** 同主题一律更新旧条（见第四节）。一天最多新增 3 条；想写第 4 条，先把一条到期的处理掉。

## 三、字段怎么填

| 字段 | 类型 | 怎么填 |
|---|---|---|
| `核心观点` | title | **一句话说清结论**，把关键数字塞进去。例：「黄金股三档防线：0.618 守不住 / 0.50 位 22.5 元 / 0.382 位 17.20 元」 |
| `作者` | select | 斯托伯 9493911686 / 新人 1910783512 / 鹿鼎公 3962719063 / **外部观点**（其他球友的有力论证） |
| `提出日期` | date | 说这话的那天（不是入库那天） |
| `观点类型` | select | 事实 / 因果链 / 预测 / 操作 / 方法论 |
| `类别` | select | 油运 / 铝 / 电力/煤炭 / 油气 / 宏观/风格 / 方法论 |
| `相关标的` | multi_select | 从现有选项里选；没有对应标的就留空，别硬套「大盘/风格」 |
| `状态` | status | 默认「待验证」；回填时改「部分兑现 / 兑现 / 证伪」 |
| `验证标准` | text | **必填**，见下 |
| `假设收益` | number(percent) | **若按此判断操作**，判断日至今的标的涨跌幅。用来把「观点跟踪」变成「策略跟踪」；没算就留空，别瞎填 |
| `复盘结论` | text | 回填时写：当时怎么核的、错在哪、对持仓有什么用。**开头必须写「数据时点：YYYY-MM-DD HH:MM（收盘 / 盘中）」** |

### 三条硬规矩（2026-11-03 加）

1. **事实与预测不同页。** 一条里同时出现「已发生的数」和「外推的数」，将来必被读错（教训：《阿能 Q4 255 亿》一条塞了 255/222/77 三个数，已拆成两条）。
2. **复盘必须标数据时点。** 盘中取的数写成「收盘」是同类错误的源头（教训：《弱反弹→泄洪》用 14:51 的成交额标了「收盘」）。
3. **规则不进台账。** 「【持仓规则】」类条目的正文一律搬进《规则｜A股交易系统》对应章节，台账里只留一条存档并在 `复盘结论` 开头写「⚠️ 已迁移至 v3.0 §X，仅存档」。台账只放作者观点。

### 验证标准必须写三件事

```
1. 看什么：具体指标 / 标的代码 / 数据源
2. 什么算兑现：可量化的阈值
3. 什么算证伪：反向阈值 + 时间窗（必须写成 YYYY-MM-DD）
```

**验证期限写在 `验证期限` 独立字段，`验证标准` 正文第一行也附上便于阅读**：

```
验证期限：2026-11-06（收盘）
```

查询到期项（利用独立 date 字段直接排序，不再靠 LIKE）：

```sql
SELECT url, "核心观点", "状态", "验证标准", "date:提出日期:start", "date:验证期限:start"
FROM "collection://685f6319-c771-43a3-b4a8-3b7ebdeb9d00"
WHERE "状态" = '待验证' AND "date:验证期限:start" IS NOT NULL
ORDER BY "date:验证期限:start" ASC
```

**反例：**「看金价走势」
**正例：**「标的紫金 601899。基准 250 日高 44.94。兑现：下探 22.5 附近。证伪：金价站回 0.618 上方、紫金收复 27.77 并站稳。时间窗 2026Q4–2027Q2。」

## 四、新建还是更新

**默认更新，不新建。**

新建之前必须先查一遍同主题有没有旧条目：

```sql
SELECT url, "核心观点", "状态", "date:提出日期:start"
FROM "collection://685f6319-c771-43a3-b4a8-3b7ebdeb9d00"
WHERE "核心观点" LIKE '%关键词%'
ORDER BY "date:提出日期:start" DESC
LIMIT 10
```

（用 `notion-query-data-sources`，`mode: "sql"`，`data_source_urls` 是**数组**。）

| 情况 | 动作 |
|---|---|
| 同一判断有了新进展 | **更新原条目的「复盘结论」+「状态」**，标题不动 |
| 同一主题但换了角度 | 更新原条目，把新角度并进复盘结论 |
| 完全新的判断 | 才新建 |

**一个主题一个条目。** 别让台账里躺着五条「黄金 780」。

## 五、怎么写（工具调用）

```js
// 新建
await tools.notion["notion-create-pages"]({
  parent: { data_source_id: "685f6319-c771-43a3-b4a8-3b7ebdeb9d00" },
  pages: [{
    properties: {
      "核心观点": "……",
      "作者": "鹿鼎公 3962719063",
      "date:提出日期:start": "2026-11-01",
      "date:验证期限:start": "2026-12-31",
      "观点类型": "预测",
      "类别": "宏观/风格",
      "相关标的": ["黄金ETF"],
      "状态": "待验证",
      "验证标准": "……"
    }
  }]
});

// 更新（必须带 command）
await tools.notion["notion-update-page"]({
  page_id: "……",
  command: "update_properties",
  properties: { "复盘结论": "……", "状态": "部分兑现" }
});
```

**踩过的坑：**

- `notion-update-page` 少了 `command` 会直接报错
- `notion-create-pages` 的 `parent` 字段名要跟当前 schema 走，改版后先看签名
- 日期属性要拆成 `date:提出日期:start` / `date:验证期限:start`
- 选项名必须和库里一字不差（含空格，如「鹿鼎公 3962719063」）
- **别用缓存下来的 page_id。** 批量更新时一条 404 会让整批中断，前面的改完、后面的全没跑（11-05 就踩了：`40801e49…` 实际是 `40901e49…`，前 2 条成功、后 4 条静默丢失）。做法：先 SQL 查出 url 再逐条更新，每条单独 try/catch，最后回查状态确认。

## 六、复盘节奏：到期制，不是「过一遍」

**每周只处理到期的，不再全量扫。** 顺序固定：

1. 查到期项（SQL 见第三节）。
2. 逐条核，能判的当场改「兑现 / 证伪 / 部分兑现」，复盘结论写依据。
3. **核不动的，直接标「证伪」+ 复盘结论写「无法验证：<缺什么数据>」**，不留「待验证」。挂着比判错更糟——它会一直占位，让你以为在跟踪。
4. 到期项清完，才允许新建。

**状态定义要严格：**

| 状态 | 什么情况用 |
|---|---|
| 兑现 | 判据里的阈值实际达到 |
| 部分兑现 | 判据有多个条件，达到一部分；或方向对、幅度不够 |
| 证伪 | 阈值没达到 / 方向反了 / 到期无法验证 |
| 待验证 | **只给未到期且确实要等的**，不是默认值 |

兑现/证伪都要写理由，不能只改状态。复盘结论里写清**「这条对持仓到底起了什么作用」**——没起作用的也要写，那是方法论在失效的信号。

## 七、核验数据源（实测可用 / 不可用，2026-11-05）

**可用：**

| 用途 | 接口 |
|---|---|
| A 股日线 | `https://money.finance.sina.com.cn/quotes_service/api/json_v2.php/CN_MarketData.getKLineData?symbol=sh601872&scale=240&ma=no&datalen=120`（返回 `day:...` 非标准 JSON，需给键名加引号再 parse） |
| A 股/美股实时价 | `https://hq.sinajs.cn/list=sh000001,gb_fro`，必须带 `-H 'Referer: https://finance.sina.com.cn'`，GBK 编码 |
| 三表/营收/归母 | `https://datacenter-web.eastmoney.com/api/data/v1/get?reportName=RPT_LICO_FN_CPD&columns=SECURITY_CODE,SECURITY_NAME_ABBR,REPORTDATE,TOTAL_OPERATE_INCOME,PARENT_NETPROFIT&filter=(SECURITY_CODE%3D%22600026%22)&pageSize=6&sortColumns=REPORTDATE&sortTypes=-1` |

**不可用（别再试）：**

- stooq CSV：JS 反爬，返回验证页
- Yahoo chart API：直接给错误页
- 长桥 MCP 美股历史 K 线：账号配额 0（`error_code 301607`），港股/美股基本面也是空
- 分部营收（外贸油运 77 亿这类）：免费接口没有，只能等财报附注/推介材料

**注意：** 用实时接口取的价，复盘里不能标「收盘」。

## 八、风格

- 大白话，不写「综上所述」
- 复盘结论只留「关键数据 + 判断 + 推翻条件」，**不要复制原文全文**
- 数字必须标来源（自己算的 / 作者说的 / 接口查的）
- 未核实的写「未核实」，别把别人的引用当事实

## 八、验证期限（2026-11-07 与 schema 改版同步）

- 台账使用独立 date 属性「验证期限」（对应数据库 `date:验证期限:start`），不再把日期塞在「验证标准」文本第一行做 LIKE 筛选。
- 新建或更新待验证条目时必须填写验证期限：预测按验证窗口最后一天；滚动指标/操作规则设下一次明确复核日；长期框架设年度复核日。
- 验证期限当天查看验证标准，能核则回填状态与复盘结论；无法核验也要明确结案，不得机械续期。
- 不确定截止点时不臆测，先核对验证标准与来源。验证期限是复核检查点，不代表判断必然在该日兑现。
- 修改此规则时，同步更新 Notion 页面「雪球作者观点跟踪」中的验证期限说明。
